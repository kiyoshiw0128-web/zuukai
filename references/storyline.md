# 筋書きの作り方

スライドの見出しだけを上から読んで、結論まで話が通じれば筋書きはできています。
図やナレーションは、その見出しを支えるために足します。

## 見出しのルール

| ルール | よくない例 | よい例 |
|---|---|---|
| 言い切りの1文にする | 会議の現状 | 会議の7割が、時間どおりに終わっていない |
| 25字以内 | 議題を事前に共有することによって会議時間の短縮が期待できる | 議題を先に送ると、会議は短くなる |
| 1枚1メッセージ | 会議が長い理由と対策 | （2枚に分ける）会議が長いのは議題がないから／議題を前日に送る |
| 聞き手の言葉で書く | アジェンダ事前配布によるMTG効率化 | 議題を先に送ると、会議は短くなる |

見出しが言い切れないときは、まだ言いたいことが決まっていません。元の資料に戻って、何が言えるかを確かめます。

## 筋書きの型

聞き手と目的に合わせて1つ選びます。迷ったら「結論 → 根拠 → 具体 → 行動」にします。

### 結論 → 根拠 → 具体 → 行動（ピラミッド）
報告、提案、勉強会の基本の形です。
1. 表紙（持ち帰る1文を副題に）
2. 結論（いちばん言いたいこと）
3. 根拠を1枚ずつ（数字や事実。「根拠」の札）
4. 具体（どうやるか。フローや判断の図）
5. 明日からやること（行動。番号つき）
6. 出典と、割り引いて読む点

### 問題 → 原因 → 対策 → 効果
改善の提案、不具合の報告に使います。原因が複数なら、ロジックツリーで漏れなく分けます。

### 空・雨・傘
空（事実：空が曇っている）→ 雨（解釈：雨が降りそう）→ 傘（行動：傘を持っていく）。
事実と解釈と行動を1枚ずつに分けると、どこまでが事実かが聞き手に伝わります。

### SCQA（状況・問題・問い・答え）
聞き手がまだ問題に気づいていないときに使います。
状況（いつもの様子）→ 問題（でも困っている）→ 問い（どうすればいい？）→ 答え。

### 比べて選ぶ
案が複数あり、決めてほしいときに使います。
選ぶ基準 → 案ごとの比較（表か2x2）→ おすすめと理由 → 決めてほしいこと。

## 根拠と提案を分ける

論文・調査・測定の結果は「根拠」、それを受けた自分たちの考えは「提案」と分けます。
- 根拠のスライドは、上に結果の図（「根拠」の札）、下の帯に「だから〜」の提案（「提案」の札）
- 提案だけを並べるスライド（明日からやること）では、各項目の右にもとにした根拠のページを書く
- 最後のスライドに「論文から言えるのはここまで」「ここからはこの資料の提案」と書き分ける

## 枚数の目安

1枚あたり30〜90秒です。10分なら8〜12枚、20分なら15〜20枚にします。
表紙・出典を入れて数えます。
